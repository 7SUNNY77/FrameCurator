# FrameCurator — протокол разметки и оценки

Версия 0.1 (неделя 0, 2026-10-04). Источник: `CLAUDE.md`, раздел 7. Изменения после пилота
(этап 1.5) записываются в `docs/experiment_log.md`; формулировка вопроса не меняется никогда.

## 1. Вопрос (фиксирован)

> «Из этого видео нужно выбрать несколько лучших кадров для фотоальбома. Какой из двух кадров вы бы взяли?»

| Клавиша | Ответ | Использование |
|---|---|---|
| 1 | Левый | Обучение и оценка ранжирования |
| 2 | Правый | Обучение и оценка ранжирования |
| 3 | Одинаково | Не участвует в обучении ранжированию |
| 4 | Оба непригодны | Не участвует в ранжировании; калибрует пороги технических отказов и фильтр reject |

Правила показа:
- Левый/правый — случайно, `choice` записывается относительно `frame_a`/`frame_b` после отмены перестановки.
- Метаданные (время кадра, номер шота, имя видео, оценки моделей) разметчику не показываются.
- Время ответа (`rt_ms`) сохраняется для каждого ответа.
- Сессии разметки — до 30 минут, ежедневные блоки по 20–30 минут.

## 2. Пулы кандидатов

Для каждого видео — пул из **P = 32** кандидатов, seed = hash(video_id):

1. По одному кадру от каждого шота (до 16 шотов, приоритет — самому резкому кадру шота).
2. По 2 кадра из каждого квинтиля score фиксированной необучаемой IQA-модели (лучший доступный
   на момент генерации кандидат; модель записывается в `pools.csv`/журнал).
3. Остальное — случайно.

Причина попадания кадра в пул сохраняется в `meta/pools.csv` (`pool_reason`: shot | score_quantile | random).

## 3. Граф сравнений

1. Случайный гамильтонов цикл по 32 кадрам пула (32 пары) — гарантирует связность графа.
2. Случайные рёбра до ~64 пар на видео (в среднем 4 сравнения на кадр).
3. Доля пар внутри одного шота — около 30%, остальные — между шотами.
4. Схема полностью детерминирована seed'ом; **модель в выборе пар не участвует** (train-база, val, test, пилот).

## 4. Active sampling (только train, после этапа 3.3)

- До 20 дополнительных пар на train-видео, где |q(a) − q(b)| у текущей модели минимальна.
- В CSV: `pair_type=active`, `sample_prob` — вероятность отбора пары.
- **Запрещено** для val, test и пилота.
- Основные CV-метрики считаются только на неактивных парах.

## 5. Объём

Ориентир: ~45 train+val видео × (64 + 20) ≈ 3800 пар; test-видео × 64 (при 20 видео ≈ 1300 пар).
При ~4 с на пару ≈ 6 часов разметки. Минимум для продолжения — 2000 пар train+val.

## 6. Контроль качества разметки

| Проверка | Процедура | Цель |
|---|---|---|
| Самосогласованность | 5% пар повторяются вслепую через ≥ 2 дня (`is_repeat=1`) | ≥ 85% |
| Второй разметчик | 15% пар, стратифицировано по видео, включая test | Согласие ≥ 70%, Cohen's kappa по ответам 1/2 |
| Быстрые ответы | `rt_ms` < 700 помечаются | Исключаются в анализе чувствительности |

Если на пилоте согласие < 70%: уточнить инструкцию (добавить примеры, **не меняя вопроса**) и
повторить пилот на 5 новых видео. Контрольная точка K1 — см. `CLAUDE.md`, раздел 11.

## 7. Схема файлов меток

```
labels/pairs_trainval.csv  pair_id, video_id, frame_a, frame_b, choice, rater, ts, rt_ms, pair_type, sample_prob, is_repeat
labels/pairs_test.csv      та же схема; читается только через load_labels("test")
labels/set_eval.csv        eval_id, video_id, rater, method_left, method_right, choice, rt_ms, is_attention_check
labels/manual_sets.csv     ручные наборы автора для 5 видео
```

## 8. Оценки Брэдли–Терри внутри пула

MLE с L2 (λ = 0.1), центрирование; для LambdaRank — квантование s внутри пула в 0–4 по
квантилям. На синтетике (n = 32, 64 пары) корреляция Спирмена с истинными s около 0.58,
поэтому NDCG и Спирмен — вторичные метрики.

## 9. Слепая оценка наборов

- Для каждого test-видео системы B1, B4, B6, Mt, Mm дают наборы по k = 8.
- Оценщик видит попарные сравнения наборов: две сетки 4×2 рядом, порядок и сторона случайны.
  Сравнения: Mm–B6, B6–B4, Mm–Mt, Mm–B4; в 50% видео — проверка внимания (метод против B1).
- Вопрос для наборов: «Какой из двух наборов вы бы взяли в фотоальбом этого видео?»
  **[РЕШИТЬ до 5.4: точная формулировка и наличие варианта «одинаково», согласовать с предрегистрацией]**.
- Наборы с Jaccard ≥ 0.75 (с допуском по шоту) не показываются, засчитывается ничья с пометкой.
- ≥ 5 внешних оценщиков на каждое test-видео; ≤ 10 видео на оценщика (~15–20 минут).
- Исключение: оценщик, выбравший B1 более чем в половине проверок внимания.
- Автор проходит оценку отдельно (`rater=author`), его ответы — вторичный показатель и H5.
- Оценщикам не сообщаются названия методов и гипотезы; манифест показа не содержит названий методов.
- Контакты оценщиков хранятся вне репозитория.
