## 1. Исследовательский вопрос

Даёт ли оценщик кадров, обученный на попарных предпочтениях одного человека (автора), наборы
из k = 8 кадров, которые **другие люди** в слепом сравнении предпочитают наборам из готовой
IQA/эстетической модели **при одинаковой стратегии отбора**? Сколько добавляет явная
оптимизация разнообразия (MMR) при фиксированном оценщике?

Проверяется перенос вкуса одного разметчика на других людей; персонализация не заявляется.

## 2. Системы (факторный дизайн 2×2 и baselines)

| | top-k | MMR (λ, m подбираются одинаковой процедурой) |
|---|---|---|
| Готовый оценщик (B4, выбирается по правилу 5.1) | **B4** | **B6** |
| Обученный оценщик (основная модель, правило 5.2) | **Mt** | **Mm** |

Дополнительно в слепой оценке: **B1** (случайный набор, seed по видео) — только для проверок
внимания. Остальные baselines (B0, B2, B3, B4a, B5) участвуют только в offline-метриках и абляциях.

## 3. Гипотезы

### 3.1 Конфирматорные (семейство с поправкой Холма, m = 3)

- **H1.** Mm побеждает B6: средняя по видео доля побед Mm > 0.5.
- **H2a.** B6 побеждает B4 (эффект MMR при готовом оценщике).
- **H2b.** Mm побеждает Mt (эффект MMR при обученном оценщике).

### 3.2 Вторичное (вне семейства Холма)

- Mm против B4 — «система целиком против готового решения»; та же процедура, без поправки.
- Pairwise accuracy основной модели минус B4 на test-парах ≥ 3 п.п.

### 3.3 Эксплораторные (только CV по train+val, на test не проверяются)

- **H3.** Ручные признаки + эмбеддинги точнее каждой группы отдельно (≥ 1.5 п.п. pairwise
  accuracy, paired bootstrap по видео); ручные признаки снижают долю технических отказов.
- **H4.** Pairwise accuracy выходит на плато к 1000 парам (проверка эквивалентности, 9.4).
- **H5.** Согласие автора с большинством внешних оценщиков на сравнениях наборов ≥ 60%.

## 4. Данные и разбиение

- Источник: собственные видео автора, 60–70 видео по 1–5 мин, ≥ 15 сессий, ≥ 2 устройства.
- Единица разбиения — **съёмочная сессия**. Видео разных сессий с pHash-дубликатами
  (расстояние Хэмминга ≤ 6) объединяются в одну группу до разбиения.
- **Test:** ≥ 20 видео из ≥ 5 сессий (точное число — **[РЕШИТЬ]** по таблице мощности, раздел 9),
  включая хотя бы одну сессию с устройством/типом сцены, редким в train. Раскладка сессий —
  перебор с фиксированным seed, стратификация по устройству и наличию людей.
- Train+val: подбор всех параметров — GroupKFold по сессии, 5 фолдов. Отдельный val-сплит
  (2–3 сессии) — только для контрольной точки K2 (этап 4.4).
- Видео с `color_profile=log` и `hdr=1`: **[РЕШИТЬ]** — тон-маппинг/LUT и включение в основной
  анализ, либо исключение. В любом случае — анализ чувствительности без них.
- Test-метки читаются только через `load_labels("test")`, который требует
  `FRAMECURATOR_FINAL_EVAL=1` и git-тег замороженной модели вида `vX.Y-frozen`.

## 5. Правила выбора (фиксируются до работы с test)

### 5.1 Выбор B4 и B4a

1. На этапе 2.1 фиксируется упорядоченный список кандидатов IQA и эстетических моделей из
   `pyiqa` (имена проверяются через `pyiqa.list_models()` в установленной версии; версия pyiqa
   записывается в журнал). **[ЗАПОЛНИТЬ: список кандидатов и версия pyiqa]**
2. Метрика: pairwise accuracy на неактивных парах train+val без ничьих (ответы 1/2),
   GroupKFold по сессии, 5 фолдов, среднее по фолдам. Модели не обучаются, поэтому фолды
   служат только для оценки разброса.
3. **B4** = IQA-кандидат с максимальной метрикой; **B4a** = эстетический кандидат с максимальной
   метрикой. При точном равенстве выбирается кандидат, стоящий раньше в списке.
4. Оценщик B4 используется в B6 без изменений.

### 5.2 Выбор основной обученной модели (Mt, Mm)

1. Кандидаты: BT-lin, BT-MLP, LGBM-rank (CLAUDE.md, 8.3), признаки v1.
2. Метрика: CV pairwise accuracy на неактивных парах (5 фолдов × 5 seed, среднее).
3. Выбирается модель с максимальной метрикой; если её преимущество над более простой моделью
   < 1 п.п., выбирается более простая. Порядок простоты: BT-lin < BT-MLP < LGBM-rank
   **[РЕШИТЬ: подтвердить порядок между BT-MLP и LGBM-rank]**.
4. Финальная модель обучается на всём train+val (для BT-MLP — среднее q по 5 seed),
   фиксируется тегом `v1.0-frozen` с хешем весов в журнале.

### 5.3 Подбор λ и m для MMR

λ ∈ {0, 0.1, 0.2, 0.3, 0.5, 0.8}, m ∈ {1, 2, ∞}. Целевая функция на CV: средняя BT-оценка набора
по пулу минус штраф за технические отказы, плюс визуальная проверка на 3 train-видео.
Процедура одинакова для Mm и B6, подбор раздельный для каждого оценщика.
**[РЕШИТЬ: вес штрафа за технические отказы в целевой функции.]**

## 6. Слепая оценка наборов (основной тест)

- Для каждого test-видео системы B1, B4, B6, Mt, Mm дают наборы по k = 8 кадров.
- Оценщику показываются попарные сравнения наборов (две сетки 4×2, порядок и сторона случайны):
  Mm–B6, B6–B4, Mm–Mt, Mm–B4; в 50% видео дополнительно проверка внимания (случайный метод
  из {B4, B6, Mt, Mm} против B1).
- Выбор вынужденный, из двух наборов **[РЕШИТЬ: вынужденный выбор или с вариантом «одинаково»]**.
- Если два набора совпадают по Jaccard ≥ 0.75 (с допуском по шоту), сравнение не показывается
  и засчитывается как ничья = 0.5 с пометкой.
- ≥ 5 внешних оценщиков на каждое test-видео, не более 10 видео на оценщика.
- Автор проходит оценку отдельно; его ответы не входят в основной анализ (вторичный показатель, H5).

### 6.1 Правило исключения оценщиков

Внешний оценщик исключается из всех анализов, если в проверках внимания он выбрал B1 более чем в
половине случаев. Исключение применяется до вычисления любых результатов по гипотезам. Число
исключённых оценщиков сообщается в отчёте.

## 7. Пороги подтверждения

| Гипотеза | Условие подтверждения |
|---|---|
| H1 | Доля побед Mm над B6 ≥ **0.60** **[РЕШИТЬ: 0.60 или 0.55 — см. раздел 9]** **и** нижняя граница bootstrap-CI по видео на уровне Холма > 0.50 |
| H2 | Для обеих пар (B6 vs B4, Mm vs Mt): нижняя граница CI на уровне Холма > 0.50 **и** среднее по видео покрытие шотов у MMR-системы выше, чем у top-k-системы (точечная оценка) |
| Вторичное | Mm vs B4: нижняя граница 95% CI > 0.50 (без поправки); pairwise accuracy основной модели − B4 ≥ 3 п.п. на test |
| H3 | Ручные + эмбеддинги лучше каждой группы на ≥ 1.5 п.п. (CV, paired bootstrap по видео) |
| H4 | Верхняя граница 95% CI прироста accuracy от 1000 пар к полному объёму < 2 п.п.; иначе — «плато не показано» |
| H5 | Согласие автора с большинством внешних оценщиков ≥ 60% по сравнениям наборов |
| Качество разметки | Самосогласованность ≥ 85%, согласие двух разметчиков ≥ 70% |

Если H1 не подтверждена, но точечная оценка Mm ≥ B6, вывод формулируется как «паритет / не
доказано», без формулировок превосходства.

## 8. План анализа

### 8.1 Основная оценка

1. Для сравнения c и test-видео v: `w_cv` = среднее по включённым внешним оценщикам индикатора
   «выбран первый метод пары» (ничьи по Jaccard = 0.5). Сначала усреднение внутри видео,
   затем по видео: `W_c = mean_v(w_cv)`.
2. Видео без единого включённого оценщика исключаются, их число сообщается.
3. Bootstrap по видео, 10 000 повторов, seed 0: перцентильный CI для `W_c`.
4. Односторонний bootstrap p-value: `p_c = (1 + #{W*_c ≤ 0.5}) / (B + 1)`.
5. **Поправка Холма** на {H1, H2a, H2b}: сравнения упорядочиваются по `p_c` по возрастанию;
   на шаге j = 1, 2, 3 используется двусторонний CI уровня `1 − 0.05/(4 − j)`; гипотеза
   подтверждается, если нижняя граница > 0.5 (и выполнено точечное условие из раздела 7);
   при первом неподтверждении все последующие не подтверждаются.

### 8.2 Устойчивость и сверки

- Кластерный bootstrap по сессии (10 000 повторов); при расхождении с bootstrap по видео в
  отчёте приводятся оба.
- Опционально: смешанная логистическая модель `win ~ 1 + (1|video) + (1|rater)`.
- Анализ чувствительности: без быстрых ответов (< 700 мс), с ответами автора, без log/HDR-видео.
- CV-результаты: 5 seed × 5 фолдов, среднее ± std и CI по видео.

### 8.3 Абляции (только CV по train+val)

A1 (группы признаков), A2 (стратегия отбора при фиксированном q), A3 (объём разметки:
200, 500, 1000, 2000, все пары; 5 подвыборок по видео), A4/A5 — если позволит время.

### 8.4 Post hoc

Всё, что получено после первого взгляда на test (анализ ошибок, дополнительные срезы, новые
модели), помечается «post hoc» и не меняет выводов по гипотезам. Повторные запуски на test
ради другого вывода запрещены.

## 9. Анализ мощности (этап 0.2)

### 9.1 Выводы из симуляции

1. **Учёт Холма существенно снижает мощность.** H1 проверяется на уровне α/3 только если её
   p-value наименьшее в семействе; если эффект MMR (H2) сильнее, H1 проверяется на уровне α/2
   или α. Реальная мощность лежит между двумя таблицами.
2. **Снижение min_point до 0.55 почти не помогает**: при p_true = 0.65 и 20 × 5 мощность
   0.743 → 0.749 (без поправки), 0.600 → 0.601 (Холм). Ограничивает условие на CI, а не
   точечный порог. Запасной вариант из CLAUDE.md 7.5 («снизить min_point до 0.55») неэффективен;
   рычаги — число видео и число оценщиков.
3. Эффект p_true = 0.60 при min_point = 0.60 обнаруживается с мощностью ≤ 0.52 в любой ячейке сетки (с min_point = 0.55 — до 0.66 при 30 × 7 без поправки).

### 9.3 Ограничения симуляции

- `sd_video = 0.15` — допущение, не оценка; не проверено на данных.
- Оценщики независимы, эффект оценщика (строгие/мягкие) не моделируется — мощность завышена.
- Ничьи по Jaccard (засчитываются 0.5) не моделируются — при частых совпадениях наборов
  Mm и B6 мощность ниже.
- Корреляция видео внутри сессии не моделируется; кластерный bootstrap по сессии даст более
  широкие CI.
