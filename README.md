# FrameCurator

Отбор качественных и разнообразных кадров из видео по попарным предпочтениям одного разметчика
с факторной проверкой «оценщик (готовая IQA / обученный) × отбор (top-k / MMR)».

## Задумка

Из одной минуты видео с дрона или телефона получаются сотни почти одинаковых кадров. Чтобы
собрать из ролика несколько снимков для альбома, их обычно перебирают вручную. Готовые модели
оценки качества изображений (IQA) не решают задачу целиком по двум причинам:

1. Они оценивают каждый кадр отдельно, поэтому top-k по их оценке — это часто несколько соседних
   кадров одного и того же момента.
2. Они измеряют техническое качество (резкость, шум, экспозицию), а человек выбирает кадр в альбом
   ещё и по содержанию и композиции.

FrameCurator проверяет, помогает ли здесь небольшое собственное обучение. Человек отвечает на
простой вопрос о паре кадров: «какой из двух вы бы взяли в альбом?». На этих ответах обучается
лёгкий оценщик кадра поверх замороженных признаков: ручных (резкость, экспозиция, лица, композиция)
и эмбеддингов DINOv2/CLIP. Набор из k кадров затем собирается жадным MMR: каждый следующий кадр
должен быть одновременно хорошим и непохожим на уже выбранные.

### Что именно проверяется

Эксперимент построен как сравнение 2×2, чтобы разделить два эффекта — что даёт обученный оценщик
и что даёт разнообразие:

| | top-k | MMR (разнообразие) |
|---|---|---|
| Готовая IQA-модель | B4 | B6 |
| Обученный оценщик | Mt | Mm |

- **Главный вопрос:** при одинаковом отборе MMR выбирают ли внешние люди в слепом сравнении
  наборы обученного оценщика (Mm) чаще, чем наборы готовой IQA (B6)?
- **Второй вопрос:** улучшает ли MMR наборы при любом из двух оценщиков (B6 против B4, Mm против Mt)?
- Дополнительно: какие группы признаков полезны, сколько разметки нужно и переносится ли вкус
  одного разметчика на других людей.

### Как устроена проверка

- Видео разбиваются на train и test **по съёмочным сессиям**, чтобы похожие кадры одной поездки
  не оказались по обе стороны разбиения.
- Test замораживается заранее. Все параметры подбираются только кросс-валидацией на train,
  а код не может прочитать test-метки вне финальной оценки.
- Гипотезы, пороги и план анализа фиксируются в [предрегистрации](docs/preregistration.md) до
  первого обращения к test. Число test-видео и оценщиков выбирается по симуляции мощности
  ([reports/power.csv](reports/power.csv)).
- Основная оценка — слепые попарные сравнения наборов внешними оценщиками, с bootstrap по видео
  и поправкой на множественные сравнения.
- Отрицательный результат («готовой IQA достаточно») считается нормальным исходом и тоже
  разбирается в отчёте.

Протокол разметки — [docs/protocol.md](docs/protocol.md), журнал экспериментов —
[docs/experiment_log.md](docs/experiment_log.md).

## Установка

```bash
python3.11 -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
make install        # или: pip install -r requirements.lock && pip install -e . --no-deps
make test lint
make power          # таблица мощности -> reports/power.csv
```

Инвентаризация видео (нужен `ffprobe` в PATH):

```bash
python scripts/inventory_videos.py /path/to/raw_videos --out data/meta/videos.csv
```
